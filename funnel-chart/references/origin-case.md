# 版式来历（改版前先读）

这套漏斗图是 2026-09-24 为 SSP/SPP 提现补贴漏斗（需求 5785）迭代出来的，前后被否掉两版，结论是固定的，不要重新发挥：

| 版本 | 做法 | 结果 |
|---|---|---|
| v1 | 每层色块内塞人数＋渗透率＋漏损胶囊，层间再挂标签 | 被否：「信息又密又不清晰」，同一数字在层内、标签、表格里出现 2–3 次 |
| v2 | 漏斗 + 右侧「漏损排行榜」面板 + 底部 7 列大宽表 | 被否：信息重复、面板与色块串行、尾部两层小到看不清 |
| **v3（当前）** | 层内只留人数；右侧一列集中放渗透率/累计/漏损；顶部 4 张 KPI 卡；底部 2 行页脚 | 定稿 |

## v3 稳定的几条

1. **一屏一种信息**：人数在层内，百分比只在右侧出现一次，绝不重复。
2. **宽度开方压缩**：按人数线性缩放时尾部两层几乎看不见；`(1 - (v/max)^0.5)` 的缩进兼顾漏斗形状和可读性。
3. **同色系渐变**（橙→红→品红→紫→蓝），末层偏冷表示收口；高饱和撞色会显得廉价。
4. **数据日期必须标**（右上角角标 + 页脚），多期数据各出一张，不混画。
5. **流失主因放右侧数据列末行红字**，不要塞进漏斗色块（曾塞过，压住色块且显得拥挤）。
6. 层间用 80% 透明连接面把色块连起来，漏斗才成"形"而不是一堆横条。

## 数据口径教训

- 用户先给比例、后给实测人数时，**以人数为准重算全部百分比**，旧的百分比（如 82%/20%/94.9%）不要留在图上。
- 报送数字自相矛盾的（截图里 `true_PV 5,411` 与"详情UV 5,700 × 94.9%"两说），出图前先跟用户确认这一列到底叫什么，别猜。
- 流失原因占比要问清分母（是"末层流失人数"还是"提交成功人数"），两种算法差好几倍。
